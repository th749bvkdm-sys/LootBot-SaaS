# تشغيل التوسعة التعليمية محليًا

الملفات في checkout محلي مستقل: `LootBot-SaaS-glass-release`، الفرع `codex/education-platform`. لم يُدفع هذا الفرع إلى GitHub ولم يُنشر. لا تُشغّل الترحيلات على قاعدة الإنتاج قبل مراجعة التغيير وإذن مستقل.

## الإعداد

1. `pnpm install --frozen-lockfile`
2. استخدم PostgreSQL محليًا وضع اتصالها في `.env` أو متغير `DATABASE_URL` في الطرفية. لا تستخدم اتصال الإنتاج للمعاينة.
3. `pnpm db:migrate` لتطبيق الترحيلات وفق سجل checksums. الترحيل الجديد `0014_education_platform.sql` إضافي ويُحافظ على الحسابات والكشوف السابقة.
4. `pnpm dev` لتشغيل المشروع بالبنية الحالية.

## معاينة جاهزة بلا قاعدة خارجية

`pnpm run education:preview` يبني الواجهة ثم يشغّل Express مقابل PostgreSQL محلي مؤقت باستخدام PGlite. البيانات في الذاكرة وتزول عند إيقاف المعاينة؛ لا توجد طلبات لقاعدة الإنتاج.

روابط الدخول المحلية: `http://127.0.0.1:5191/__preview/admin`، `/__preview/manager`، `/__preview/teacher`، `/__preview/student`، `/__preview/content`، `/__preview/support`، `/__preview/pending`. هذه المسارات موجودة في برنامج الاختبار المحلي وحده ولا تدخل build الخادم الإنتاجي.

المعاينة تشمل أسئلة أصلية محلية وفصلًا وحسابات تجريبية واضحة. لا توجد درجات تدريب مصطنعة: يُنشأ التقدم عند الإجابة فعليًا من الواجهة أو اختبار HTTP.

## أول مدير نظام

سجّل حسابًا بالبنية الحالية أولًا، وتأكد أنه حسابك. في بيئة محلية أو بيئة مخوّلة، عيّن `EDUCATION_BOOTSTRAP_EMAIL` لبريد ذلك الحساب، ثم `node scripts/bootstrap-education-admin.mjs`. العملية ترفض إذا كان مدير نظام موجودًا، ولا تغيّر كلمات المرور، وتسجل الحدث. لا يوجد تعيين تلقائي للإدارة بناءً على بريد يكتبه زائر.

## دورة المدرسة والطالب

1. المدير الأعلى يفتح `/admin/education` وينشئ مدرسة.
2. في المستخدمين يسند مدير مدرسة ومعلمًا مسجلًا للمدرسة.
3. مدير المدرسة يفتح `/education` ويربط فصلًا موجودًا أو ينشئ فصلًا لصاحب الحساب المسند. الفصل يستخدم `teacher_classes` الحالي.
4. من رموز الانضمام يحدد الصلاحية وعدد الاستخدامات وطلب الموافقة. يظهر النص مرة واحدة فقط، وتُخزن SHA-256 لبصمته.
5. الطالب يسجّل حسابًا ويختار «طالب»، ثم يدخل الرمز في `/student`.
6. المعلم/مدير المدرسة يوافق على الطلب عند الحاجة. يظهر الطالب في كشف الفصل نفسه.
7. يمكن استيراد حسابات طلاب مسجلة عبر CSV بعمود `email`، مع مراجعة جميع الصفوف ومنع التكرار قبل معاملة الحفظ.

## القدرات

التصنيفات الأولية الـ٢٣ محفوظة في قاعدة البيانات وقابلة للتعديل والترتيب والأرشفة. مسؤول المحتوى ينشئ سؤالًا مع الإجابة والبدائل والشروح والمصدر وإذن الاستخدام. يرسله للمراجعة؛ ناشر آخر ينشره عندما تكون المراجعة مفعّلة. الإصدارات محفوظة والاستعادة تُنشئ مسودة جديدة. استيراد JSON يراجع التكرار ويحفظ الدفعة ذريًا كمسودات.

الطالب يختار كميًا أو لفظيًا، تدريب مهارة أو اختبارًا تشخيصيًا/تجريبيًا أو مراجعة أخطاء، مع مؤقت اختياري. الخادم يصحح من النسخة المحفوظة ويمنع إرسال مفتاح الحل قبل التسليم في الاختبارات. التدريب دون مؤقت يمكن إيقافه واستكماله. التعلم الزمني لا يتوقف. الخطة والتوصيات تشرح عدد المحاولات والأخطاء؛ لا توجد درجة مضمونة أو خدمة AI غير مهيأة.

## الاختبارات

- `pnpm typecheck`
- `pnpm --filter @workspace/lootbot build`
- `pnpm --filter @workspace/api-server build`
- من `artifacts/api-server`: `node tests/run-teacher-local.mjs tests/education-integration.ts`
- الاختبارات الموجودة للمعلم والأنشطة: `node tests/run-teacher-local.mjs tests/teacher-integration.ts` و`tests/learning-integration.ts`.

المعاينة والاختبارات محلية. خادم PGlite يدعم اتصال PostgreSQL واحدًا في هذا المسار؛ طلبات HTTP المتزامنة تُختبر مع طابور اتصال. اختبار تنافس معاملات مستقلة على PostgreSQL خادم كامل يحتاج قاعدة اختبار مخوّلة، ولا يُدّعى تنفيذه على الإنتاج.
