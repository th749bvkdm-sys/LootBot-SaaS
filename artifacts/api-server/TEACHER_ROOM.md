# غرفة المعلم — التشغيل والتحقق

تمت إضافة غرفة المعلم إلى تطبيق React/Express الحالي. لا يحتاج التحرير اليدوي إلى خدمة خارجية.

## قاعدة البيانات والتشغيل

1. احتفظ بنسخة احتياطية من قاعدة بياناتك قبل أي ترقية تشغيلية.
2. اضبط `DATABASE_URL` في بيئة الخادم، ثم شغّل أمر المشروع المعتاد `node scripts/run-pnpm.mjs run db:migrate` بعد الحصول على إذن ترقية تلك البيئة.
3. الترحيل `0010_teacher_room.sql` يضيف نوع الحساب وبيانات المعلم فقط. الحسابات السابقة تبقى `merchant`، بينما التسجيل الجديد يبدأ دون اختيار. لا يحذف الترحيل بيانات المتاجر.
4. البناء: `node scripts/run-pnpm.mjs run build`. التشغيل المحلي: `node scripts/run-pnpm.mjs run dev`.

إعداد Render يستخدم `db:migrate` فقط بعد بناء التطبيق. إذا احتفظت لوحة Render بأمر بناء قديم يستدعي `db:push` من جذر المستودع، فإن `scripts/run-db-push.mjs` يحوّله إلى الترحيلات فقط عندما يكون `RENDER=true` أو `NODE_ENV=production`. في التطوير المحلي يبقى الأمر إنشاء/مطابقة المخطط ثم الترحيلات. لا تنفذ هذه الحماية `drizzle-kit push` في الإنتاج، ولا تستخدم `--force`.

هذه الترحيلات ترقي قاعدة LootBot قائمة؛ لا تنشئ المخطط الأساسي لقاعدة جديدة فارغة. تحتاج قاعدة جديدة إلى إعداد أساسي منفصل ومراجع ومصرح به قبل الترحيلات. لا تغير عنوان قاعدة الخدمة القائمة أو سر الجلسة أثناء هذه الترقية.

عند بناء جميع حزم المستودع، يتطلب مشروع `mockup-sandbox` القائم متغيري `PORT` و`BASE_PATH`. استُخدما في تحقق البناء على PowerShell بالقيم `$env:PORT='5192'` و`$env:BASE_PATH='/'`؛ لا يُضاف خادم مستقل لغرفة المعلم.

لا تشغّل ترحيلًا ضد قاعدة الإنتاج بغرض الاختبار. اختبار القبول يستعمل قاعدة محلية مؤقتة أو مخططًا مؤقتًا داخل فرع الاختبار المعزول.

## حدود الأدوار والخصوصية

- نوع الحساب منفصل عن `OWNER` و`SUPERADMIN`؛ لا يرقّي المستخدم إلى مشرف.
- اختيار الدور محفوظ مرة واحدة. التبديل بين التاجر والمعلم غير مدعوم حاليًا؛ لا تُحذف أي بيانات لتبديل الدور.
- كل واجهات المعلم تتطلب جلسة صحيحة وملكية البيانات؛ كل كتابة تتحقق من CSRF.
- تُحفظ الصور في قاعدة البيانات، ويُقرأ محتواها من مسار خاص بالجـلسة مع `Cache-Control: no-store`. ليست هناك روابط صور عامة.
- JPEG/PNG/WebP فقط، بحد 8 ميجابايت و40 مليون بكسل. PDF غير مدعوم في هذه المرحلة.
- استيراد الكشوف CSV مع معاينة وتحقق واختيار إضافة/تحديث. يمكن تحويل Excel إلى CSV UTF-8 قبل الاستيراد؛ لم يُضَف محلل Excel غير موجود إلى تطبيق الإنتاج.
- حذف الطالب حذف قابل للاسترجاع من مرشح المؤرشفين والمحذوفين. النقل يحافظ على معرف الطالب وتاريخ الحضور والدرجات.
- لا تستخدم أسماء الطلاب أو الملاحظات في الروابط أو سجلات الخادم. البحث يستخدم جسم POST.

## الاستخراج من صور الاختبارات

الوضع الافتراضي **يدوي**: تُعرض الصورة الخاصة بجانب الأسئلة القابلة للتحرير، مع ضبط الصورة والحفظ وإعادة الفتح والطباعة. لا تُعرض نتيجة OCR مخترعة.

يوجد محول اختياري إلى Azure Vision Read 3.2. تمت مطابقة الطلب الثنائي، وترويسة `Operation-Location`، وحالات المعالجة، وبنية الأسطر مع [وثائق Microsoft الرسمية](https://learn.microsoft.com/en-us/azure/ai-services/computer-vision/how-to/call-read-api). لم يتم إرسال صور حقيقية إلى خدمة خارجية أثناء التنفيذ، ولم يُختبر حساب Azure فعلي.

للتمكين في بيئة الخادم فقط:

```text
TEACHER_OCR_PROVIDER=azure-read
TEACHER_OCR_ENDPOINT=https://<resource-name>.cognitiveservices.azure.com/
TEACHER_OCR_KEY=<server-secret>
```

لا تحفظ المفتاح في الشفرة أو ملفات المشروع أو متغيرات `VITE_*`. يتطلب هذا إنشاء مورد Azure Vision أو استخدام مورد مناسب قائم، وقد تنتج عنه رسوم وفق حسابك. اختيار هذا المحول يعني إرسال الصورة التي طلب المستخدم استخراجها إلى Azure. تستخدم الشفرة مهلة محدودة، وتمنع إعادة التوجيه إلى مصدر آخر، وتعود إلى رسالة تحرير يدوي عند الفشل. لا تستنتج الإجابات أو الدرجات؛ كل نص مستخرج يحتاج مراجعة المعلم.

## الأتمتة الداخلية

يبدأ عامل المعلم مع خادم API، ويفحص القواعد المستحقة كل دقيقة. يدعم مواعيد المهام والاختبارات، حد الغياب، الدرجات غير المرصودة، الملخص الأسبوعي، المسودات، والتذكيرات المتكررة. الجدولة بالساعات تستخدم UTC. السجلات المحفوظة ومفاتيح عدم التكرار تمنع تكرار إجراء القاعدة نفسه، والمعالجة تستخدم معاملات وقفل `SKIP LOCKED`.

التذكيرات داخل غرفة المعلم فقط. لا تُرسل رسائل لأولياء الأمور. يتطلب التشغيل في موعده بقاء خدمة API قيد التشغيل؛ الاستضافة التي تدخل وضع النوم تعالج القواعد المستحقة عند استئناف الخادم. `TEACHER_WORKER_DISABLED=true` مخصص لتعطيل العامل في الاختبارات، وليس مطلوبًا للتشغيل العادي.

في قاعدة تذكير المواعيد، اختيار فصل يقيّدها بواجبات الفصل ومهامه. اختيار جميع الفصول يشمل مواعيد الاختبارات كذلك؛ وصف الصف في ورقة الاختبار لا يُستخدم لتخمين ارتباطه بفصل محفوظ. لا يوجد مرشح فصل لقواعد المسودات أو التذكيرات الدورية الحرة.

## الاختبارات

```text
node scripts/run-pnpm.mjs run typecheck:libs
node scripts/run-pnpm.mjs --filter @workspace/api-server run typecheck
node scripts/run-pnpm.mjs --filter @workspace/api-server run test
```

اختبارات `teacher-validation.test.mjs` و`teacher-ocr.test.mjs` تستخدم بيانات وأجوبة خدمة تجريبية فقط. اختبار `tests/teacher-integration.ts` يجرب HTTP حقيقيًا وحفظ الأدوار والبيانات، CSRF، عزل الملكية، استيراد الطلاب، حفظ الحضور، الدرجات، الصور الخاصة، الحفظ المتزامن للاختبار، القوالب، وعدم تكرار الأتمتة. محول OCR اختُبر ببروتوكول محاكى؛ لا يُعد هذا تحققًا من حساب خارجي أو جودة التعرف على صور عربية حقيقية.

### اختبار PostgreSQL محلي دون بيانات حقيقية

من مجلد `artifacts/api-server`، بعد تثبيت اعتماديات التطوير:

```text
node tests/run-teacher-local.mjs tests/teacher-integration.ts
node tests/run-teacher-local.mjs tests/storefront-integration.ts
node tests/run-teacher-local.mjs tests/api-integration.ts
```

ينشئ المشغّل قاعدة PGlite مؤقتة في الذاكرة، يجهز مخطط التاجر السابق دون بياناته، ثم يطبق الترحيل مرتين للتحقق من إمكانية إعادة تشغيله وبقاء حساب سابق كتاجر. يشغل تطبيق Express نفسه عبر HTTP وواجهة PostgreSQL المحلية، ويحذف الملفات المؤقتة عند انتهاء الاختبار. PGlite اعتماد تطوير فقط؛ قاعدة التشغيل تبقى PostgreSQL المعتادة. محاكاته لاتصال قاعدة واحدة لا تثبت سلوك عدة خوادم إنتاج متزامنة.

اختبارات نموذج محرر الورقة وCSV، من جذر المستودع:

```text
node --test artifacts/lootbot/src/lib/teacher-exam-model.test.mjs artifacts/lootbot/src/components/teacher-roster-utils.test.mjs
```

### اختبارات الواجهة

ابنِ واجهة التطبيق أولًا، ثم من `artifacts/api-server`:

```text
node tests/run-teacher-local.mjs tests/teacher-ui-server.ts --serve
```

تتوفر نسخة محلية ببيانات وهمية فقط على `http://127.0.0.1:5190`. ليست هذه قاعدة الاستخدام اليومي، وتنتهي بياناتها عند إيقافها. لإيقاف نسخة `--serve` اكتب `stop` في طرفيتها أو استخدم Ctrl+C.

من جذر المستودع، بعد توفير Playwright ومتصفح Chromium محلي:

```powershell
$env:PLAYWRIGHT_MODULE = '<absolute-path-to-playwright/index.mjs>'
$env:BROWSER_EXECUTABLE = '<absolute-path-to-chrome-or-msedge.exe>'
$env:TEACHER_QA_URL = 'http://127.0.0.1:5190'
$env:TEACHER_UI_URL = 'http://127.0.0.1:5190'
node artifacts/lootbot/tests/teacher-browser-acceptance.mjs
node artifacts/lootbot/tests/teacher-exam-browser.mjs
node artifacts/lootbot/tests/storefront-browser.mjs
```

شغّل اختبارات المتصفح بالتتابع، لأن بعضها يعدل البيانات الوهمية المشتركة. تنشأ تقارير JSON ولقطات وملفات PDF تجريبية في `artifacts/lootbot/test-results`. يستخدم اختبار PDF مكتبة `pdf-lib` من بيئة الأدوات المحلية، ويمكن ضبط `PDF_LIB_MODULE` لمسارها عند الحاجة؛ ليست مكتبة تشغيل مطلوبة للتطبيق. الاختبارات ترفض عناوين الخدمات الخارجية.

## مظاهر المتجر

يختار التاجر من إعدادات متجره: داكن، أبيض، أو `LootBot Nebula`. المعاينة تعرض المنتجات المنشورة الفعلية فقط. يُحفظ الاختيار داخل `store_settings.settings.storefront` مع الحفاظ على بقية إعدادات البوت والخطة.

مسار الكتالوج العام: `/store/:slug`، والتصنيفات: `/store/:slug/categories/:categoryId`، والتفاصيل: `/store/:slug/products/:productId`. العرض العام معطل افتراضيًا ويتطلب تفعيلًا صريحًا من التاجر. يستمر الطلب عبر بوت المتجر المتصل عندما يكون متاحًا؛ لم يضف هذا التغيير بوابة دفع أو تجربة شراء جديدة. استجابات المظهر والكتالوج لا تُخزن مؤقتًا حتى يسري تغيير المظهر أو إغلاق الكتالوج عند تحديث الصفحة.

## قبل الإتاحة للمستخدمين

هذه الملفات تجهيز محلي؛ لم تُرفع إلى GitHub ولم تُنشر، ولم يُطبّق الترحيل على الإنتاج. بعد مراجعة التغييرات والموافقة على نشرها، استخدم مسار نشر المشروع القائم وطبّق `0010` في قاعدة التشغيل المعتمدة. لا يحتاج التشغيل اليدوي إلى مفتاح OCR أو خدمة جديدة.
